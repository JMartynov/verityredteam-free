    1. Problem Statement & Audit Summary¶

    Currently, verityredteam-free/README.md (89 lines) reads like an internal open-core migration note instead of a customer-facing product guide: 1. No end-user install path: Only shows uv run verity ... (assumes contributor git clone); omits uvx --from verity-redteam-core verity ... and pip install verity-redteam-core. 2. Misses major Free capabilities already in code: - Python AST code scanner (verity scan --path, 9 VERITY-AST-* rules covering CWE-94, CWE-78, CWE-22, CWE-502, CWE-79, CWE-862), - Live MCP server probing (verity test --command for stdio and --url for HTTP/SSE), - CI/CD gating (--fail-on-findings exit code 1), --config-file, --schema-file, --format json|markdown|html, --output, - Exact list of the 9 supported AI clients (Claude Desktop, Cursor, VS Code Cline, VS Code Roo, Continue, Windsurf, Zed, LibreChat, workspace .mcp.json), - Threat categories caught by all 13 VERITY-STATIC-* rules (+ NFKC / zero-width Unicode normalization), - IDE MCP server mode (verity serve --transport {stdio,sse,http}, /health, 4 unified MCP tools + python -m verity.mcp_server.manage), - Unknown Capability Profiler (src/verity/ucp/engine.py) rug-pull drift detection (detect_rug_pull), - Embeddable SqlSecurityGuard Python library API (src/verity/mcp_library/sql_guard.py). 3. Contains inaccurate / mismatched output: - Hand-mocked verity test --demo table (Target | CWE | Result -> VULN) does not match actual CLI output (Status | Check | Severity | Message -> PASS with Vulnerable breached=True, Secure defended=True). - Static docs/assets/demo.svg uses wrong package name verity-core. 4. Heavy focus on plugin internals: ~25% of the README is Python entry_points boilerplate better suited for a linked docs/extensibility.md.
