    Installation¶

    Verity runs on macOS, Linux, and Windows, with first-class support for developer laptops, CI runners, air-gapped environments, and security research workstations. Choose the path that matches your environment, then wire the IDE client of your choice to the shared MCP server.

    Customer Environment Selector Guide¶

    Environment Recommended install Why Key flags
    Developer workstation brew or uvx Isolated env, fast updates, zero global pollution verity scan --path .
    CI/CD pipeline pip or container Pinned versions, deterministic cache --fail-on-findings --format json
    Air-gapped / regulated Source or offline wheel Full artifact control --offline
    Security researcher uv tool or source Isolated env, editable checkout --target ... --demo

    Prerequisites¶

    • Python 3.12 or newer (<3.15) for pip, uvx, uv tool, and source installs.
    • A supported IDE client for MCP integration.
    • Optional: Docker 24+ only if you choose the container path.
    $ python --version
Python 3.12.4

    Install with uvx¶

    uvx runs Verity in an ephemeral environment, which is ideal for one-off scans and trying the CLI without modifying global state.

    $ curl -LsSf https://astral.sh/uv/install.sh | sh
$ uvx verity-redteam-core scan --offline
$ uvx verity-redteam-core scan --path . --format terminal
# Legacy two-token form (equivalent):
$ uvx --from verity-redteam-core verity scan --offline

    Pin a version in automation:

    $ uvx verity-redteam-core==0.2.2 scan --path . --fail-on-findings
# Or with --from:
$ uvx --from verity-redteam-core==0.2.2 verity scan --path . --fail-on-findings

    Install with pip¶

    Use a virtual environment or the CI runner's managed environment.

    $ python -m venv .venv
$ source .venv/bin/activate
$ python -m pip install --upgrade pip
$ python -m pip install "verity-redteam-core==0.2.2"
$ verity scan --help

    $ python -m pip install --upgrade verity-redteam-core

    Install with uv tool¶

    uv tool installs an isolated CLI binary while keeping it on PATH.

    $ uv tool install verity-redteam-core
$ uv tool list
verity-redteam-core v0.2.2

$ verity scan --help

    Upgrade or uninstall:

    $ uv tool upgrade verity-redteam-core
$ uv tool uninstall verity-redteam-core

    Install with Homebrew¶

    Install Verity on macOS (Apple Silicon or Intel) or Linux (Linuxbrew) via the official tap JMartynov/homebrew-tap.

    Prerequisites¶

    • Homebrew installed on macOS or Linux.
    • Zero Python or virtualenv management required: Formula/verity.rb uses Language::Python::Virtualenv to build a self-contained virtualenv with python@3.13, libyaml, and pinned PyPI sdist SHA-256 resources, isolated from your system or project Python environments.

    Installation options¶

    Two-step install (recommended for easy tap discovery and updates):

    $ brew tap JMartynov/tap
$ brew install verity

    Single-command install:

    $ brew install JMartynov/tap/verity

    Verify the Homebrew installation¶

    $ verity --version
verity 0.2.2
$ which verity
/opt/homebrew/bin/verity
$ brew test JMartynov/tap/verity

    First-run usage steps after installing via Homebrew¶

    Run the zero-Docker offline self-test demo to verify SQLi, BOLA, NoSQLi, and code-injection checks end to end:

    $ verity test --demo

    Discover and audit local MCP clients (Claude Desktop, Cursor, VS Code, Windsurf, Cline, and more) either with default settings or strictly offline:

    $ verity scan
$ verity scan --offline

    Scan a project directory or MCP server repository (SAST + OSV advisories + typosquatting + CycloneDX SBOM export):

    $ verity scan --path ./my-mcp-server
$ verity scan --offline --format cyclonedx --scanners vuln --output sbom.json

    Gate brownfield repositories in CI with a deterministic baseline and severity threshold:

    $ verity scan --path . --save-baseline .verity-baseline.json
$ verity scan --path . --baseline .verity-baseline.json --fail-on-new --fail-on-severity high

    Run Verity as a local stdio MCP server for IDE agents:

    $ verity serve

    Add Verity to your client's mcpServers block. Because Homebrew symlinks verity into a standard bin directory (/opt/homebrew/bin/verity on Apple Silicon, /usr/local/bin/verity on Intel macOS, or /home/linuxbrew/.linuxbrew/bin/verity on Linux), GUI apps such as Claude Desktop and Cursor can launch it reliably without inheriting shell pyenv or .venv PATH configuration:

    {
  "mcpServers": {
    "verity": {
      "command": "verity",
      "args": ["serve"]
    }
  }
}

    If a GUI app does not include Homebrew's bin directory in its launch environment, set "command" to the full path reported by which verity (for example "/opt/homebrew/bin/verity").

    Upgrading, inspecting & uninstalling¶

    $ brew update && brew upgrade verity
$ brew info JMartynov/tap/verity
$ brew uninstall verity
$ brew untap JMartynov/tap

    Stage B (Homebrew/homebrew-core) Graduation: Verity ships via JMartynov/homebrew-tap immediately. Graduation to Homebrew/homebrew-core requires meeting notability thresholds (≥75 stars / ≥30 forks for third-party submissions, or ≥225 stars / ≥90 forks for self-submissions) and validating Python 3.15 so requires-python can be lifted from >=3.12,<3.15 to >=3.12,<3.16.

    Install with Docker¶

    Run Verity from the official Python 3.12 image and mount the working directory for scanning.

    $ docker run --rm \
    -v "$PWD:/work" \
    -w /work \
    python:3.12-slim \
    sh -c "pip install verity-redteam-core==0.2.2 && verity scan --path . --format json"

    For CI, pin the image digest instead of the tag.

    Install from source¶

    Use this path for air-gapped builds, contribution, or deep inspection.

    $ git clone https://github.com/JMartynov/verityredteam-free.git
$ cd verityredteam-free
$ uv sync
$ uv run verity scan --help

    Build an offline wheel for transfer:

    $ uv build
$ ls dist
verity_redteam_core-0.2.2-py3-none-any.whl

    Verify the installation¶

    $ verity scan --offline
$ verity test --demo
$ python -c "import verity; print(verity.__version__)"
0.2.2

    Shared MCP server entry¶

    Most clients accept the same command block. Adapt the key name where required (mcpServers, context_servers, or IDE-specific schema).

    {
  "mcpServers": {
    "verity": {
      "command": "verity",
      "args": ["serve", "--transport", "stdio"]
    }
  }
}

    For Continue:

    {
  "mcpServers": [
    {
      "name": "verity",
      "command": "verity",
      "args": ["serve", "--transport", "stdio"]
    }
  ]
}

    For Zed:

    {
  "context_servers": {
    "verity": {
      "command": {
        "path": "verity",
        "args": ["serve", "--transport", "stdio"]
      }
    }
  }
}

    Troubleshooting FAQ¶

    1. uvx: command not found¶

    $ uvx --from verity-redteam-core verity scan --offline
zsh: command not found: uvx

    Install uv and reopen the shell so ~/.local/bin is on PATH.

    $ curl -LsSf https://astral.sh/uv/install.sh | sh
$ exec "$SHELL"
$ uvx --from verity-redteam-core verity scan --offline

    2. Permission denied writing an MCP config¶

    Add the verity server entry directly to the client JSON config. If the file or directory is not writable:

    $ verity scan --config-file "$HOME/Library/Application Support/Claude/claude_desktop_config.json"
error: permission denied: /Users/dev/Library/Application Support/Claude/claude_desktop_config.json

    Fix ownership or run the client once so it creates the directory, then retry.

    $ mkdir -p "$HOME/Library/Application Support/Claude"
$ chmod u+rw "$HOME/Library/Application Support/Claude"
$ verity scan --config-file "$HOME/Library/Application Support/Claude/claude_desktop_config.json"

    3. Python version mismatch¶

    $ python -m pip install verity-redteam-core
ERROR: Package 'verity-redteam-core' requires a different Python: 3.9.6 not in '>=3.12,<3.15'

    Use a supported interpreter explicitly.

    $ uv python install 3.12
$ uv venv --python 3.12
$ uv pip install verity-redteam-core
$ verity scan --help

    4. Homebrew tap not found or outdated metadata¶

    $ brew install verity
Error: No available formula with the name "verity".

    Tap the repository and refresh Homebrew's tap metadata:

    $ brew tap JMartynov/tap
$ brew update
$ brew install verity
$ verity --version

    If brew upgrade verity reports that the latest version is already installed right after a new PyPI release, run brew update && brew upgrade verity to pull the updated Formula/verity.rb.

    5. Docker daemon unavailable¶

    $ docker run --rm python:3.12-slim verity scan --offline
Cannot connect to the Docker daemon at unix:///var/run/docker.sock.

    Start Docker and retry.

    $ docker run --rm \
    -v "$PWD:/work" \
    -w /work \
    python:3.12-slim \
    sh -c "pip install verity-redteam-core==0.2.2 && verity scan --path . --format json"

    6. IDE does not list verity as an MCP server¶

    $ verity serve --transport stdio
error: command not found in client PATH

    GUI desktop apps often do not inherit shell PATH entries from pyenv, uv, or .venv activations. Use the absolute Homebrew path (/opt/homebrew/bin/verity on Apple Silicon macOS, /usr/local/bin/verity on Intel macOS, /home/linuxbrew/.linuxbrew/bin/verity on Linux) or the path returned by which verity:

    $ which verity
/opt/homebrew/bin/verity

    {
  "mcpServers": {
    "verity": {
      "command": "/opt/homebrew/bin/verity",
      "args": ["serve"]
    }
  }
}

    Restart the IDE, then confirm discovery with a manual stdio handshake:

    $ printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"manual","version":"1.0.0"}}}' '{"jsonrpc":"2.0","method":"notifications/initialized"}' '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' | verity serve --transport stdio

    The response lists the four unified tools: verity_security_scan, verity_database_guard, verity_database_oracle, and verity_remediation_ops.

    7. Air-gapped or offline environments¶

    Pass --offline (or set VERITY_OFFLINE=1) so verity scan disables remote snapshot fetching and relies strictly on the bundled fingerprint and OSV caches:

    $ verity scan --offline
$ verity scan --path ./my-mcp-server --offline

    Uninstall¶

    $ uv tool uninstall verity-redteam-core
$ brew uninstall verity
$ brew untap JMartynov/tap
$ python -m pip uninstall -y verity-redteam-core

    Remove any verity entry from the MCP config paths listed above, then restart the IDE client.
